id: show-real-thing
step: concept
principle: Each beat shows a real artifact working: the real UI for a real product, the brand's own mark and world for an invented one. A word in a box is not a beat.
limit: no text under 28 px at 1920 wide on a built screen
range: a capture, a drawn real artifact or a live demo in every beat that makes a claim; a product screen is designed for the video, never a plain mock, and a capture of the real product beats a mock: one focal element per screen, the subject fills most of the frame, real images whole at the source aspect ratio, colour from theme tokens with one accent
break-when: a film whose whole idea is type on a field, decided on purpose and defended in the brief
instead: render a mini-scene so the viewer watches the thing work (a value changes and the output updates; the real word cycles through colours). If a cursor clicks, the next frames show what the click did. For a real product, capture the real UI. For an invented product the brief asks you to invent the UI: design it as a real interface (the builder skill of the ladder, real-looking data, controls that do something; the frame rejects web-page patterns, the UI parts do not), then place it in the frame. Only fake chrome with no function, or a placeholder label, is the pitfall. Build a screen as a real interface first, then place it under the density budget: a fragment for the shot with large type, few elements, real imagery. Set each cell to the source's own aspect ratio so object-fit: cover neither crops nor letterboxes. A dark capture goes on a dark surface.
check: judge
judge: Name the artifact that earns each beat. Which beat holds only a word in a box, chrome with no function or a click with no result? Does the screen look designed for the film, and is every claim in its copy true?
prevents: feedback: "it shows so little" (launch film). About 4 in 10 shipped scenes carried no picture of any size and the median film gave about 5 percent of its layers to picture. doc TASTE.md: "produced, not generated". A hand-written mock defaults to a grey window, small type and a sparse grid: reference acts measured fill 0.71 against a first mock's 0.17.
