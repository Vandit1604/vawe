The invariantrenderFrame(n) is a pure function of n

Everything else is downstream of this one sentence. The Go renderer opens several headless tabs and gives each a different slice of the timeline, so a frame must not depend on which frame was drawn before it. Break that and the film is wrong in a way no single frame reveals.

Stage twoOne frame, in order

Two bugs in one week were ordering rather than arithmetic, so the order is now written down and lib-test parses it out of the doc. BUILD runs once at boot. FRAME is renderFrame(n), top to bottom.

build   measure → becomes → childOffsets
frame   drawBg → driveClips → driveSceneUnits → resolveBoxes → runTracks
        → drawCaptions → drawCameraAndCut → drawStings → drawSeams → seekAll

resolveBoxes runs before any track, so scene.boxOf(id) is authored geometry plus the motion track plus the enter pose, and nothing a track wrote. It is not a live DOM read. A follow therefore cannot chain, and chaining is refused by name rather than left to arithmetic.

The boardWhat is worth fixing, ranked

Each item names its evidence and where the fix belongs. The house rule is that a gate is the last resort: if the bad value has a write site, the refusal goes there and the class of bug ends.

The transform accumulator was never emptied fixed today

Four tracks prepend to el.style.transform, which is only safe if something clears it each frame. driveClips cleared a property only when one of the layer's own animations wrote it, so a layer entering on wipe, iris or clock (all clip-path, no transform) composed onto whatever string the previously rendered frame left behind. Order-dependent by construction.

clipStyleAt now returns transform: "none" unconditionally, before the resting keys and the composed style, so any animation that does write a transform still wins.

evidence · turning the idle default on quarantined linear-agents at scale 0.9897 forwards, 0.9694 backwards. The bug predated the idle; the idle gave it a second voice.
fix · core/timeline/clips.js, one frozen constant, two spread sites.

Relative time: the diagnosis was wrong, the holes were real fixed

This page said "a group does not scope its children's clock". Two mechanisms already do. resolveRelativeStarts takes start: "otherId+0.5", used 26 times, and a group child's window is its group's window offset by delay, used 279 times. Containment scopes time here exactly as it scopes geometry. I named the concept and did not grep the codebase's name for it.

Three real holes in the feature that is there, all now closed:

resolveRelativeStarts walked the top level and stopped, so anything nested could neither be a target nor resolve its own. Nothing failed: the string reached the DOM, parseFloat("hero+0.4") is NaN, NaN || 0 is 0, and the layer started at zero with every gate green. It walks the whole tree now and refuses a string that survives the passes. .end on a target with no duration scored an invented ?? 2; it names the layer instead. And a group child's own start / duration are read off the group and the child's discarded, which 49 children across 13 films do today: warned in the validator, not refused, because honouring an absolute start would let a child outlive the group containing it.

fix · formats/scene/scene.js, core/validate/validate.mjs, pinned in lint-test in both directions, with the asserts watched failing.

The adjustment layer built

{ "type": "adjust", "kind": "blur", "amount": 22 } grades every layer with a lower track and leaves everything above it crisp. Five kinds (blur, desaturate, darken, brighten, contrast) plus a raw filter escape hatch.

Short, because nothing here is new machinery. backdrop-filter was already carrying the glass look; track was already the z-index, so "beneath" needed defining, not building; and the CSS reads var(--adjust), so the existing vars track keys it rather than a second keying mechanism for one layer type. Adding the type meant one file, one line in the registry, and the schema generator picked up its props on its own.

verified by render · text on track 1 and the ground blur, text on track 3 stays sharp, and --adjust reads 0.0000 → 0.5781 → 1.0000 across an easeOutCubic ramp.

Depth exists and is unreachable p1 · named, not fixed

core/fx/plane.js diagnoses this in its own header: every layer sits at z = 0, so a camera move turns the whole composition as one rigid pane. Three films of 134 use it, and 44 of the 47 films with a camera move have every layer at z = 0.

make preflight now carries a NOT REACHED FOR section that names depth for a film in that state, with the share of the library beside it. Deliberately not a gate: a wrong depth is worse than none, and a capability nobody knows about is a discovery problem, which you answer where the author is deciding rather than by refusing the film afterwards. Adoption is the open half.

CI can compare snapshots now fixed

The ceiling was written down as permanent and it was a size problem. 20MB of full signatures cannot be committed; 4.2KB of sha256 can. quality/baselines/snap/digest.json is the one tracked file in a gitignored directory, and a checkout without the baselines falls back to it for a whether-it-moved verdict, saying so rather than implying the full net ran. The what stays local, where the 20MB lives and a person can read a diff.

Only honest because the faces are pinned: scripts/media/fonts.mjs carries an exact version and a sha256 per face, and refuses a mismatch. This page said that was still unpinned. It has not been for some time, and one of the pins carries a comment explaining why GeistMono sits on 5.2.8 rather than 5.3.0.

The populations are reachable fixed

The code has had one owner for "the library" since census.mjs. The docs did not, because there was no way to ASK, and this page produced a fifth number by hand on the morning it was written. make census prints each named population, the question it answers, and how many of it a fresh clone sees.

134 library  ·  152 library+derivatives  ·  159 every scene file  ·  106 what the snapshot net sweeps. Quote a name.

The linear easings were a measurement question p3 · answered

"41% of easings are linear" was one number doing two jobs. Split by segment length it is three: 15% sit on a segment shorter than DENSE_KEY_SEC (0.14s), where core/timeline/sequence.js interpolates linearly anyway and naming it is documentation; 28% sit on a longer span across 22 films, which is the real question; and 58% carry a named curve.

No code change, deliberately. linear-motion is already a ratcheted code, so the blocking case is covered, and higgsfield-recreation is in that 28% on purpose: its interior keys are linear because the surge and give-up of a real hand is what makes the pan read as somebody's. A gate here would manufacture defects.

Sixty-five gates is a surface, not only a net p3 · watch

Two have already been deleted for measuring the wrong thing. visual-vocabulary squared a 590×18 rule into 590×590 and credited a hairline with a tenth of the frame; make slop ran 41 borrowed rules against a DOM dump carrying evidence for three of them and reported its silence as a pass. A wrong gate is worse than no gate, because it manufactures confidence.
