vawe · animation

How we animate things

There is one idea underneath all of it. Everything else is a detail hanging off that idea. This deck explains the idea first, then the details, in plain words.

Sister page: how the whole engine works.

01 · the big idea

It is a flipbook, not a video

Nothing in this engine ever plays. We draw one still picture, save it, throw it away, and draw the next one.

A video player has a film running past a lamp. Our engine has a stack of paper. We ask it "what does picture number 47 look like?", it draws exactly that, we take a photograph of it, and we move on to 48.

At the end we have 900 photographs. We staple them together into an mp4. That is the whole render.

A video player

Time flows. The picture changes because time passed.

Time does not flow. The picture changes because we asked for a different number.

02 · the one rule

Picture 47 must always look the same

Ask for picture 47 first, or last, or twice, or on another computer. You must get the same picture every time. That is the single rule the whole engine is built around.

Drag the slider. You are doing exactly what the renderer does, one number at a time.

47

Press "jump around". It asks for frames in a scrambled order. The box still lands in the right place for each number, because the position is worked out from the number, not from wherever the box happened to be a moment ago.

03 · the trick

We lie to the browser about the time

Here is the awkward part. We draw with a real web browser, and browsers are full of things that want time to pass on their own. Animations. Timers. Math.random().

So before we draw picture 47, we quietly reset the browser's sense of time to 1.56 seconds, which is where frame 47 sits at 30 pictures a second.

  1. The clock now reads 1.56s, no matter what the real clock says.
  2. Any timer due before 1.56s fires now, in order.
  3. Random numbers restart from a seed made out of the number 47.
  4. We draw. We photograph. We move to 48 and do it again.

The page believes 1.56 seconds have passed. Nothing has. This is why the same frame always paints the same picture, even though we are drawing inside a live browser.

Where it lives: installVirtualClock() in core/boot.js.

04 · the pieces

A layer is just a box with a job

Everything you see on screen is a layer. A layer is a rectangle that knows where it sits, how big it is, when it appears, and what kind of thing it is.

The kindWhat it puts on screen
textWords. The most common one by far.
imageA picture from a file.
rectA coloured block or a card.
componentA real piece of a real website, captured live.
groupSeveral layers that move together.
countA number that counts up.

Each kind is one file in core/layers/. Adding a new kind means adding a file and one line in a list. That is on purpose.

05 · how a layer moves

You state where it is at a few moments

You do not describe the movement. You state where the thing is at two or three moments, and the engine fills in every picture between them.

// "start at the left, small. End at the right, big."
"motion": [
  { "t": 0,   "dx": 0,   "scale": 0.8 },
  { "t": 2.5, "dx": 600, "scale": 1.2, "ease": "brake" }
]

Those moments are called keys. Between two keys the engine works out the in-between position for whichever picture it is drawing.

ease is the feel of it. linear moves at one steady speed and looks mechanical. brake arrives fast and settles. Real things almost never move at a constant speed, which is why steady motion reads as cheap.

06 · arriving and leaving

Coming in, and going out

Most layers do not simply exist. They arrive, they sit still for a while, and they leave. You name the arrival and the departure, and the engine handles the ramps.

"anim": "slide-right",   // how it arrives
"out":  "slide-left",    // how it leaves
"start": 2.0, "duration": 3.5

The house rule: if a thing enters from the right, it should leave to the left. One direction of travel. A layer that slides in and then retreats the way it came looks like a mistake, and the gates flag it as enter-and-retreat.

When moving would fight the content, leave through focus instead of through space: out: "defocus". That is the right call for faces, for cards, and for dense grids, where sliding fifty things at once reads as chaos.

07 · one picture, step by step

What actually happens for one frame

For every layer, on every picture, the engine runs through a fixed list of jobs. Each one may adjust the layer. They happen in this order, and the order matters.

  1. The cut. If a cut owns this moment, it decides the arrival and exit look.
  2. Kinetic type. Words or letters revealed one at a time.
  3. Cut-out letters. The ransom look re-rolls each glyph.
  4. The layer's own job. A counter counts, a line types, a pointer moves along its path.
  5. The trail. The light that runs around a border.
  6. The ring. Text set on a circle turns.
  7. Live values. Numbers the layer's own styling reads, driven over time.
  8. Sound. Reactions to the music, read from a table baked before the render.
  9. The box track. Width and height, if they are being animated.
  10. The motion track. Position, scale, rotation, opacity, from your keys.
  11. Modifiers. Last, always. Next slide.

Each job is one file in core/tracks/, and each file names the slot it runs in. The order above is a single list in core/tracks/index.js, and it is the only place the order lives. Two jobs asking for the same slot is an error the engine refuses to start with, so "modifiers are last" is a rule the code holds rather than a sentence in a comment.

One thing worth knowing: a layer outside its window still runs the list. Most jobs check the clock and do nothing. The box track does not, on purpose. Width is a value nothing else rewrites, so a size left behind by a later picture would still be there if you jumped backwards, and the same picture would then look different depending on what you watched first.

08 · modifiers

Things done to a layer

A layer kind answers "what is this thing?". A modifier answers "what is done to it?" It is not a new thing on screen. It changes something already there.

{ "type": "image", "src": "/card.png",
  "modifiers": [ { "tilt": { "y": 12 } }, { "shadow": 30 } ] }

tilt

Leans the layer in 3D. Everything on screen leans toward one shared vanishing point, like one camera is looking at all of it.

occlude

Hides this layer wherever another named layer covers it, so one thing can pass behind another.

shadow

Casts a shadow away from the scene's light. Move the light and every shadow turns.

mixBlend

Decides how this layer's colours mix with what is already painted behind it.

Why this matters: an effect used to have to be a layer to exist at all. That is why the engine has five separate kinds that all just paint a glowing field. A modifier applies to whatever is already there, so effects stop being things you place.

09 · the backdrop

The background is a decision, not a default

Every film must state its backdrop. There is no blank. A still, flat colour is a choice you are making, and usually the wrong one.

The backdrop is painted first, underneath every layer, and it moves on the same clock as everything else. Same rule: its look at picture 47 is worked out from the number 47.

Judge it across pictures, never on one. A single still hides speed, scale and direction. A background was once "matched" to a reference on one frame and was, in motion, twice too fast with shapes half the right size.

10 · into a file

From pictures to an mp4

  1. A small Go program starts a web server and opens a headless browser.
  2. The browser loads the scene and reports how long the film is.
  3. Go asks for picture 0, waits for it to paint, photographs it. Then 1. Then 2.
  4. Several browser tabs do this at once, each taking a different stretch of numbers.
  5. ffmpeg stitches the photographs into a video and adds the sound.

Step 4 is only possible because of the one rule. If picture 47 depended on picture 46 having been drawn first, you could not hand different stretches to different tabs. Splitting the work across tabs is what the whole design buys you.

11 · why

What the one rule pays for

It is fast

Four tabs draw four stretches at once, because no stretch needs another one first.

It is repeatable

The same file gives the same video today and next month. Nothing drifts.

You can scrub it

Jump straight to any second and see it, with no render and no waiting.

Bugs stay put

A broken frame is broken every time you look at it, so it can be found.

Every awkward thing in this engine is the price of that rule. It is worth it.
