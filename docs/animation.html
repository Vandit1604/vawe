vawe / how we animate things

Nothing here
ever plays.

The engine draws one still picture, photographs it, discards it, and draws the next. There is no film running past a lamp. Understand that one sentence and every strange thing about this engine turns into a consequence of it.

the rule

Picture 47 must always
look like picture 47

Ask for it first, last, twice, or on another machine. Same picture every time. Everything below is built on that.

FRAME 00
sample · 1920×1080 · 30 fps 000/090   t 0.000s   x 0px
renderFrame(0)

You ask for a number

The renderer never says "advance". It says "draw picture 0", then "draw picture 1". The number is the only thing it hands over.

renderFrame(47)

The picture is worked out from it

Where the card sits is calculated from 47. Not from where it was on 46, because 46 may never have been drawn at all.

renderFrame(90)

Nothing is remembered

Each picture is thrown away once it has been photographed. Nothing carries forward, so nothing can drift.

out of order

Which is why order does not matter

Press scramble. It asks for frames in a jumbled order and every one lands correctly. That is not a trick. It is what lets four browser tabs each render a different stretch at once.

the awkward part

We lie to the browser
about the time

We draw with a real browser, and browsers are full of things that want time to pass on their own. Timers. Date.now(). Math.random().

So before drawing picture 47, the engine quietly resets the page's sense of time to 1.567 seconds, which is where frame 47 sits at 30 pictures a second.

// core/boot.js · installVirtualClock()
vt.ms = (frame / fps) * 1000;              // the clock now reads 1567
rnd   = (frame * 2654435761) | 0;          // random restarts from a seed made of 47
for (const t of timers) if (t.at <= vt.ms) t.cb();   // anything due fires, in order

The page believes 1.567 seconds have passed. Nothing has.

And the half that cannot be patched. JavaScript cannot reach the browser's compositor clock, so a CSS animation or transition would keep running on wall-clock time and render as a dead still. The engine does not try. It bans them in core/tokens.css, and the validator rejects any hand-written HTML containing one, pointing you at var(--t) instead. Same answer for video: there is no <video> element anywhere, and a clip layer swaps an <img> source per frame. Patch what can be patched, ban what cannot, and prove it with a purity gate on every build.

the pieces

A layer is a box
with a job

Everything on screen is a layer: a rectangle that knows where it sits, how big it is, when it appears, and what kind of thing it is. text, image, rect, group, count, and a live component captured out of a real website.

one file each

A layer kind is one file in core/layers/ exporting two functions, plus one line in a registry. That is the whole cost of a new primitive.

an unknown kind is an error

It used to fall through to the text builder, which paints nothing when there is no text. A scene could render an empty film and exit zero.

four were secretly one

paint, shader, raymarch and three each made a canvas and drew from local time. They now share one primitive with four backends.

how a layer moves

State where it is at
a few moments

You never describe the movement. You give two or three moments, and the engine works out every picture in between.

ease · brake checking… t 0.000s   eased 0.000   scale 0.80
"ease": "brake"

Arrive fast, then settle

Most of the distance is covered early and the last few pixels take their time, which is how anything with weight actually behaves.

"ease": "linear"

One steady speed

Switch to this and watch it go cheap. Nothing physical moves at a constant rate, so the eye reads it as a computer sliding a rectangle. The gates flag a film built out of it.

"ease": "spring"

Overshoot, then come back

Real spring physics. It passes the target and returns. Used sparingly it feels alive; used everywhere it feels like a toy.

"ease": "ramp"

Slow, fast, slow

The editor's speed ramp. Velocity is low at both ends and peaks in the middle, which reads as deliberate camera work rather than a lerp.

// two keys and a feel. everything between them is calculated.
"motion": [
  { "t": 0,   "dx": 0,   "scale": 0.8 },
  { "t": 2.5, "dx": 600, "scale": 1.2, "ease": "brake" }
]

one picture, step by step

Twelve jobs, in an order
the code enforces

For every layer, on every picture, the engine runs the same list. Scroll to walk it.

  1. 01The cut. If a cut owns this moment, it decides the arrival and exit look.
  2. 02Kinetic type. Words or letters revealed one at a time.
  3. 03Cut-out letters. The ransom look re-rolls each glyph.
  4. 04The layer's own job. A counter counts, a line types, a pointer moves along its path.
  5. 05The trail. The light that runs around a border.
  6. 06The ring. Text set on a circle turns.
  7. 07Live values. Numbers the layer's own styling reads, driven over time.
  8. 08Sound. Reactions to the music, from a table baked before the render.
  9. 09The box track. Width and height, if they are animated.
  10. 10Follow. Pin this layer to where another layer is right now.
  11. 11The motion track. Position, scale, rotation, opacity, from your keys.
  12. 12Modifiers. Last, always.
core/tracks/

Each job is one file

And each file names the slot it runs in. The order beside you is a single list in core/tracks/index.js, and that is the only place it lives.

slot · primitive

The middle one is load-bearing

The layer's own job sits in the middle, and it has to. A cursor writes its position outright, so it must run after the cut to be allowed to override it. And every job after it composes onto whatever is already there, which is the only reason a cursor's path reaches the screen. Move it either way and both break silently.

slot · box

One job ignores the clock

The box track runs even when the layer is off screen. Width is a layout property nothing else rewrites, so a value left behind by a later frame would survive a seek backwards. Everything else checks the clock; this one deliberately does not.

collision → error

"Modifiers are last" is now enforced

It used to be a sentence in a comment, true only because of where one line sat in a long function. Two jobs claiming the same slot is now an error the engine refuses to start with.

modifiers

Things done to a layer

A layer kind answers "what is this thing". A modifier answers "what is done to it". It puts nothing new on screen; it changes something already there.

{ "type": "image", "src": "/card.png",
  "modifiers": [ { "tilt": { "y": 12 } }, { "shadow": 30 } ] }

tilt

Leans the layer in 3D. Everything leans toward one shared vanishing point, as though a single camera were looking at all of it.

occlude

Hides this layer wherever a named layer covers it, so one thing can pass behind another.

shadow

Cast away from the scene's light. Move the light and every shadow turns.

mixBlend

How this layer's colours combine with what is already painted behind it.

Why the slot exists. An effect used to have to be a layer to exist at all, which is how four separate kinds ended up each drawing a field into a canvas. A modifier applies to whatever is already there, so an effect stops being a thing you place.

into a file

From pictures
to an mp4

A small Go program starts a server and opens a headless browser. The browser loads the scene and reports how long the film is. Go asks for picture 0, waits for it to paint, photographs it. Then 1. Then 2. Several tabs do this at once, each taking a different stretch. ffmpeg stitches the photographs together and adds the sound.

That fourth step is only possible because of the rule. If picture 47 depended on picture 46 having been drawn first, you could not hand different stretches to different tabs. Splitting the work is what the whole design buys.

fast

Four tabs draw four stretches at once, because no stretch needs another one first.

repeatable

The same file gives the same video today and next month.

scrubbable

Jump straight to any second and see it, with no render and no waiting.

debuggable

A broken frame is broken every time you look at it, so it can be found.

Every awkward thing in this engine is the price of that one rule. It is worth it.
