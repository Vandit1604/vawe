vawe · how we animate things

Nothing here
ever plays.

The engine draws one still picture, photographs it, throws it away, and draws the next. There is no film running past a lamp. It is a flipbook.

the one rule

Ask for a number,
get a picture

The renderer never says "keep going". It says draw picture 47. Where everything sits is worked out from 47, and from nothing else. So picture 47 looks the same whether you ask for it first, last, or twice.

FRAME 00
000/090   t 0.000s

Shuffle asks for frames out of order. Each still lands correctly, because nothing depends on the frame before it. That is why four browser tabs can render four stretches at once.

the awkward part

We lie about the time

Browsers are full of things that want time to pass on their own: timers, Date.now(), Math.random(). So before drawing picture 47, the engine sets the page's clock to 1.567 seconds, where frame 47 lands at 30 per second.

// core/boot.js
vt.ms = (frame / fps) * 1000;       // the clock now reads 1567
rnd   = (frame * 2654435761) | 0;   // random restarts, seeded by the frame

The page believes 1.567 seconds went by. None did.

What it cannot patch, it bans. JavaScript cannot freeze the browser's own animation clock, so CSS animation and transition are not allowed in a scene. The validator rejects them and points at var(--t), which the engine writes every frame.

the pieces

A layer is a box
with a job

Everything on screen is a layer: a rectangle that knows where it sits, how big it is, and when it appears. The job is its type.

text puts words up. image shows a picture. rect is a block. count counts up. component is a real piece of a real website, captured live. group moves several layers together.

Each type is a single file with two functions, plus one line in a registry. Adding a new type is adding a file.

how a layer moves

Say where it is, twice

You never describe the movement. You say where the thing is at two or three moments, and the engine fills in every picture between them. ease is the feel of it.

GO
eased 0.000

Brake covers most of the distance early, then settles. That is how anything with weight moves.

one picture, step by step

Twelve jobs, in order

For every layer, on every picture, the engine runs the same twelve jobs. Each is one file in core/tracks/, and each names its own place in the list.

  1. The cut · how it arrives and leaves
  2. Kinetic type · words one at a time
  3. Cut-out letters · the ransom look
  4. The layer's own job · a counter counts
  5. The trail · light around a border
  6. The ring · text set on a circle
  7. Live values · numbers the styling reads
  8. Sound · reactions to the music
  9. The box track · width and height
  10. Follow · stick to another layer
  11. The motion track · position, scale, rotation
  12. Modifiers · last, always
The order used to be nothing more than the order the lines sat in, inside one long function. Now each job declares its slot, and two jobs claiming one slot is an error the engine refuses to start with.

modifiers

Change what is
already there

A type answers "what is this thing". A modifier answers "what is done to it". It puts nothing new on screen.

{ "type": "image", "src": "/card.png",
  "modifiers": [ { "tilt": { "y": 12 } }, { "shadow": 30 } ] }

tilt leans it in 3D. occlude hides it where another layer covers it. shadow casts away from the scene's light. mixBlend decides how its colours mix with what is behind.

and then

It becomes a file

A Go program opens a headless browser, asks for picture 0, waits for it to paint, and photographs it. Then 1. Then 2. Several tabs do this at once. ffmpeg stitches the photographs together and adds the sound.

Every awkward thing in this engine is the price of one rule: the same number always gives the same picture. It is worth it.
