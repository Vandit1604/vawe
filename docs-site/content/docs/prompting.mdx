Most videos are written by agents, not by hand. You describe the film in a brief, and an agent expands it into a full plan during stage 2 (planning). The agent composes the scene JSON, you iterate on renders, and `make ship` gates the result.

Vawe agents read `CLAUDE.md` and `AGENTS.md` at the repo root, so they already know the house rules, the vocabulary and the quality gates. Your job is to supply the vision, not the engine.

## The anatomy: two layers

Users rarely write full prompts. An agent expands every request into the anatomy below during planning, the way prompt expansion works in other video engines. A human may supply any part and the agent preserves it.

### Layer 1: the brief

This is who, what, why. Supply what you know. The agent keeps it and fills blanks.

```
SUBJECT   what it is about, in one line
DATA      where the facts come from (a URL, a file, an API, or "here they are")
PAYOFF    the one thing to remember, and it lands LAST
AUDIENCE  who watches, and where they see it
FEELING   one reference, or one word ("cinematic", "loud", "like Linear's launch")
```

Two more lines are unasked (the agent writes them if you do not):

| Line | What it does |
|---|---|
| `SPECTACLE` | the ONE exaggerated moment, named: which beat, which layer, which device |
| `NOT` | what this film explicitly does not do (no narration, no stock photos, no gradient hero) |

`SPECTACLE` is two-sided by purpose. Naming the loud moment is also a promise that every other beat stays restrained. A film where four beats shout has no loud moment, it has a volume setting.

`NOT` is cheaper than it looks. Most generic output is not a wrong decision, it is an un-excluded default: nothing said "no gradient hero", so a gradient hero was free.

### Layer 2: the direction

This is what and how. The agent writes these during planning stage 2 from your brief, a reference (if you point at a website), and the engine's own recipes. The agent fills it into the plan and the storyboard.

```
SPEC          duration (seconds), aspect ratio (16:9, 9:16, 1:1, 4:5, 4:3), mood key ("energetic", "contemplative")
BEATS         timestamped beat table: each beat names element, motion, layout, style, timing
COPY          exact on-screen words in quotes; unquoted copy gets rewritten
TECHNIQUE     vawe primitives or blocks by their real names (search "make arsenal Q=…" first)
NEGATIVES     what this direction explicitly does not use (no parallax, no type dissolve)
```

This layer is derived from HyperFrames' direction anatomy (https://hyperframes.heygen.com/prompting): the agent applies the same structure to Vawe scenes.

## Beat formula

One sentence per beat. Name the thing moving, how it moves, where on screen, what colour or style, and when.

**Example:** "Intro beat, 0-2s. The Vawe logo enters from top-left with a shimmer effect, lands center-top in white, holds 1s, exits down-right with a spin exit, fully out by 2s."

The formula is `element` + `motion` + `layout` + `style` + `timing` in one sentence. Vawe names every primitive you can use; search before writing anything by hand. Run `make arsenal Q="logo enter"` to find what the engine already owns.

## Specification dial

How much direction you write depends on the stage and the budget. The agent reads the dial and fills the rest.

| Dial | What you write | What the agent decides |
|---|---|---|
| **Sparse** | Brief only (SUBJECT, PAYOFF, FEELING). One page. | All direction. Full visual spec. Timing. Layout. Pacing. |
| **Moderate** | Brief + BEATS (timestamped, element names). A beat per scene. | Palette, type, motion effects, camera, sound. Visual style from FEELING. |
| **Full** | Both layers in detail. BEATS name motion, COPY is exact, TECHNIQUE names every primitive, NEGATIVES exclude what you do not want. A short scene doc. | Nothing. The agent assembles what you wrote. |

Low budget (one agent, short timeline): sparse to moderate. High fidelity (a full team, launch film, brand reflection): full, with a reference source.

## Examples

**One-liner to full brief:** You say "A one-minute launch for Vawe, show the product working."

The agent writes, during planning:
```
SUBJECT   Vawe: render video from scene JSON
DATA      https://vawe.sh (crawl every page and the docs)
PAYOFF    the same input always produces the same output
AUDIENCE  developers, on landing page, 16:9, silent autoplay
FEELING   clean and precise, like a well-written API docs page
SPECTACLE the moment a JSON file renders, frame-by-frame, in real time
NOT       no narration, no stock photos, no gradient backgrounds
```

**Full two-layer example for a launch film:**

```
SUBJECT   Acme ships Acme Tint, a color picker for design tools
DATA      https://acme.design/tint (crawl every page)
PAYOFF    one click from any app
AUDIENCE  designers on X and Dribbble, 16:9 and 1:1
FEELING   playful and precise, like Figma's own UI
SPECTACLE the moment the color picker opens and the 10,000 color grid animates in
NOT       no stock video, no loud music, no "AI" language, only real UI from the site

SPEC      60 seconds, 16:9 and 1:1, energetic and clean
BEATS     
  0-3s:   Acme logo enters from left, settles center, text "Tint" fades in below. White on dark navy.
  3-6s:   Three product screens tile in from the right edge, staggered. Each shows a part of the UI.
  6-10s:  The color grid enters with a wave effect, 10,000 color dots cascade in from top-left.
  10-14s: A cursor clicks the grid. One color isolates to center, expands to fill frame, other colors fade.
  14-17s: The color value appears as hex code, RGB, HSL in three text blocks that slide in from edges.
  17-20s: Acme logo and "One click from any app" message travel to the bottom. Everything else fades.
COPY      Frame 0: "Acme Tint"
          Frame 10: "10,000 colors in one place"
          Frame 14: "One click from anywhere"
          Frame 20: "Acme Tint. One click from any app."
TECHNIQUE wave entrance (color dots), isolate + expand (focus), cascade motion (text), all in 60fps
NEGATIVES no type morphing, no 3D camera moves, no background motion during text reads
```

## Inputs that raise quality

- **A real product URL, crawled, not invented.** `make sections` pulls the site's own colours, fonts,
  and favicon; a launch video must crawl every page and use captured UI, never a guessed one.
- **A reference film or site.** `make study REF=` measures it (shot timing, seam gaps, axis, ground
  colour); `make ideate REF=` then builds the film's structure from those real numbers, not a guess.
- **Real data.** Numbers, copy, and figures must be true and looked up, never invented for effect.
- **The video type, if you know it.** Naming "launch video," "explainer," or "a short sting" saves a
  routing step (`engine-doctrine/CRAFT/ROUTING.md`); otherwise the agent infers it from the brief.

## Words that work

The engine resolves plain words to real values in the slot each belongs to. An unknown word errors,
naming the near misses, instead of silently defaulting.

| Class | Example words | Resolves to |
|---|---|---|
| Feel | `snappy`, `soft`, `sharp`, `bouncy` | an easing curve |
| Duration | `instant`, `fast`, `medium`, `slow` | a number of seconds |
| Camera | `push in`, `pull back`, `dive`, `sweep` | a named camera move |
| Comparative | `faster`, `slower` | one step from the current value |

Full generated tables: `engine-doctrine/CRAFT/VOCABULARY.md` and, per primitive,
`engine-doctrine/CRAFT/PRIMITIVES-VOCABULARY.md` (both regenerate with `make vocab`).

## What to avoid

- **Don't ask for a template.** There are none: every film composes from
  `engine-doctrine/PRIMITIVES.md`; a scaffold is a shell, not a reusable layout.
- **No em-dashes in on-screen copy.** The validator rejects them; use a comma, a period, or a middot.
- **Don't invent UI.** A screen, logo, or photo the plan names must trace to a real capture
  (`make capture`/`make assets`); a fragment with no real source is blocked before it ships.

## What you are NOT deciding

Palette, typography, layout, motion, camera, cuts, backdrop, sound, pacing, structure. All of it belongs to whoever composes the scene, and all of it is defensible from the brief.

Reaching for engine vocabulary (naming a colour, an easing, a layer type) is a sign the brief above is underspecified. The fix is a better PAYOFF or FEELING line, not a hex code.

## The loop

Once the brief is agreed, the work is a loop, not a single shot.

```bash
make dev  D=films/scene/<film>.json    # build, draft render, open. No gates, no audit.
make check D=films/scene/<film>.json   # every gate, every finding, zero consequence
make ship  D=films/scene/<film>.json   # the ladder with its teeth in
```

`make dev` is where nearly all the time goes. `make ship` is the one command that says a film is done: it runs the author checks, renders, audits the layout and inspects the transitions, in that order.

<Callout>
**Green gates do not mean the film is good.** They read structure. They cannot see murk, a weak focal point, or a beat that lands wrong. Read the contact sheets: `make beats` for what each beat holds, `make reveal` for how each one enters and exits, `make judge` for a scored sheet and a rubric.
</Callout>

## What to say when it is wrong

Be concrete about the SYMPTOM and leave the cause alone. "Beat three reads as a slide, nothing moves but the text" is worth ten times "make it more dynamic". The agent can find the cause; it cannot guess what you saw.

If you want a different direction rather than a fix, go back to `FEELING` and `NOT`. Those two lines move a film further than any note about a specific layer.
