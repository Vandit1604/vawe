# GATE-CLASSIFICATION.md: mechanism, or result?

_GENERATED by `node quality/gates/gate-classification.mjs`. Do not hand-edit; edit the CLASSIFY table in that
file (each entry is evidence cited from the gate's own source, never a keyword guess) and regenerate._

The thesis this table exists to check (`engine-doctrine/gates-measure-the-result` plan): a gate that COUNTS a
mechanism in the JSON (an entry in `transitions[]`, a background preset, `parts` on a parent group)
misfires on any film whose craft uses a different mechanism to reach the same result. A gate that MEASURES
the result (real luminance across the real rendered seam, real changed pixels between real frames) does
not. `vawe-flow-2.json` is the film that proved it: four MECHANISM codes fired on it wrongly, while
`seam-snap.mjs`, a RESULT gate, passed it clean.

**refused** = the gate ran and found a real problem. **no-run** = a precondition was absent (no render, no
receipt, no reference, a timeout) and the gate never got to measure anything; both used to be counted as
one "blocked" number (`harness/dev/gate-census.mjs`, before this table's Task 0). **waived** = an author
wrote `authoring.allow` against a code this gate owns: the closest thing to a vote against the rule.
